# AW115MST

AWBotNest V2 的 115 文件秒传与整理插件，核心功能直接内置，不需要启动独立 AW115MST 服务。只使用平台 HTTP、定时任务、通知和管理员接口。

## 运行要求

- Python **3.12 或以上**；插件启用时由平台安装声明的 Python 依赖。支持 Windows / Linux；原项目的 GUI 和独立 Telegram Bot 轮询不包含在插件中。
- 输入目录必须在平台所在机器可访问。Docker 使用**容器内的挂载路径**，不能填写宿主机上不存在于容器内的路径。
- 相对路径以插件数据目录为基准。默认分别为 `待检测`、`可秒传`、`待秒传`；输入目录需要自行创建并放入文件。三个目录不能相同、互相嵌套、使用符号链接或指向文件系统根目录。
- Cookie 可以手动填写或扫码获取；为空时读取平台同步的 `115.com` Cookie。扫码确认后新 Cookie **保存到本插件配置**，接口和日志不返回凭据。
- 扫码默认使用 115 管理 Android 客户端槽位。请选择不与常用登录冲突的客户端，避免同槽位设备互相退出。

## 文件处理

1. 文件稳定后读取 SHA1，并在网络验证和本地整理时检查文件快照；隐藏文件和下载临时扩展名默认跳过。
2. 按配置的目标目录 ID 和子目录向 115 发起秒传初始化。**秒传命中会实际把文件加入网盘，不是只读查询**。目录创建失败会保留本地文件，不回退到网盘根目录。
3. 已确认秒传的文件复制到 `可秒传`，暂不可秒传的文件复制到 `待秒传`。默认保留源文件、保持目录结构；同名文件自动加后缀，不覆盖已有文件。
4. 重检只处理记录中的待秒传文件。默认最多重检 10 次；达到上限后下一轮可选真实上传，开关关闭时只保留文件。上限为 `0` 表示无限重检，**不会自动进入真实上传**。
5. 网络结果不明时记录为“网盘结果待核对”，不自动重复上传，也不删除本地文件。核对网盘后可清空处理记录重新扫描；清空记录不会删除文件，但可能再次加入已有网盘文件。

“不处理本地文件”仅关闭本地复制、移动和删除，仍会发起秒传入库。真实上传、所有删除选项、目录巡检、定时检测和通知默认关闭。**移动或删除只能在你明确打开相应配置后执行**；重检确认后是否删除输入源文件另有独立开关，内容已变化的源文件会保留。

每轮任务串行处理；单文件失败继续下一项，登录失效则停止本轮。停止后会等待文件 I/O 和记录保存结束，再释放任务。处理记录存储在插件数据目录下的 `checkpoints.sqlite3`，重启保留。

更换 115 账号不会自动清空记录；已经完成或结果不明的记录仍保留防重保护，请核对后按需清空再检测。未完成文件的重检会按当前账号重新查找远程目录，不复用旧账号目录 ID；旧账号已确认的入库回执不能触发新账号下的本地删除。

## 自动任务与控制

目录巡检默认间隔 5 秒，通过平台定时任务检查目录，不是操作系统事件监听。定时检测默认间隔 30 分钟，可选包含待秒传重检。关闭自动任务仍可以在配置页立即检测、立即重检或停止任务。

可选 Telegram 私聊命令：`/mst_scan`、`/mst_recheck`、`/mst_status`、`/mst_stop`。需要平台已连接 Bot，且配置允许操作的数字用户 ID；未授权用户和群聊不执行任何命令。未开启控制时不注册消息监听。

配置页和管理员 API 提供状态、最近 100 条记录、扫码登录与清空记录；不提供公开 Webhook。自动空轮询不刷 INFO 日志。
