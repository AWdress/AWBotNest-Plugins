# 远程打印

AWBotNest V2 插件。平台在服务器或 Docker 中接收 Telegram / 企业微信文件，默认通过 IPP 向局域网打印机提交任务，可借助已有 FRP 隧道连接；不要求 Windows 电脑运行打印端。也可切换为 Windows 电脑主动领取模式。不修改平台、FRP 配置或系统默认打印机。

## 支持范围

- PDF 文档、JPG/JPEG、PNG、WebP、BMP 单张图片；Office 文档请先另存为 PDF。
- Telegram：使用平台绑定或默认 Bot，仅接收允许用户的私聊，不监听群里的文件；断线恢复或切换平台绑定后自动重新接入。
- 企业微信：企业自建应用的加密消息回调；群机器人不能接收用户上传文件，不适用于远程打印。
- IPP 模式：固定连接一台支持 IPP Print-Job 的打印机。打印机需原生支持 PDF / JPEG；PNG、WebP、BMP 自动转换为单张 JPEG。图片明确使用 `print-scaling=fit`，保留完整内容和原图比例，不裁切、不拉伸；比例与纸张不同会留白，长图缩小到一页，不自动拆页。设备未声明支持 `fit` 时拒绝图片任务，不改用 `auto` / `fill`。PDF 保持原文档页面，不改变其版式。
- Windows 模式：一台 Windows 10/11 电脑，可选择它允许列表内的多台打印机，电脑端需 Python 3.10+。彩色/双面/纸张/指定页码的远程参数暂不提供，使用打印机默认设置或本地驱动设置。

## 1. 配置服务器插件

安装并启用插件后，在原生配置页填写：

1. 打印连接方式默认为“VPS / FRP 直连 IPP”。填写“IPP / FRP 访问地址”，必须是服务器或容器能访问的 HTTP(S) 地址，包含打印路径，例如 `http://打印机IP:631/ipp/print`。FRP 映射后替换主机和端口，保留打印路径。这里不填平台域名，也不填 `ipp://`。
2. 使用企业微信时填写平台外网 HTTPS 地址，例如 `https://bot.example.com`。如反代部署在子路径，可以填写 `https://bot.example.com/aw`。仅 Telegram + IPP 时可留空。Windows 模式另按下节配置设备和密钥。
3. Telegram Bot 和企业微信自建应用在**平台系统设置**配置，插件直接读取，不再填写渠道凭据或开关。这里只填写允许打印的用户；未填写对应允许列表时不接受任何用户。
4. 开启“接收远程打印任务”。“收到文件后自动打印”默认关闭：收件后需要单独确认。

保存后插件按平台机制重载。IPP 模式先点击“测试 IPP 连接（不打印）”，读取名称、状态和支持格式；该按钮不会发送打印任务。“打印机原生 URI”通常留空，自动使用设备报告的 URI；若 FRP 下设备拒绝探测，可填写打印机自身的 `ipp://局域网IP:631/ipp/print`，这与服务器访问地址是两个不同字段。

点击“查看回调地址与打印机”可以查看企微 Webhook、电脑端地址及设备状态。“查看企业微信接收配置”显示打印回调地址；Token / AESKey 直接读取平台，不在插件按钮中显示，详见下方企微设置。默认份数 1，最多 3 份；默认文件 20 MiB、50 页、30 个活动任务、总存储 200 MiB，文件保留 24 小时。原生表单显示默认值，电脑密钥独立隐藏并可点眼睛查看。接收任务和自动打印默认关闭；切换连接方式只显示对应设置，不删除已保存的另一种模式配置。

### FRP 与 Docker 注意事项

FRP 在局域网端转发打印机的 TCP 631 端口。以下假设打印机地址为 `192.168.1.50`，frpc 的 TCP 代理示例为（地址和端口需替换）：

```toml
[[proxies]]
name = "printer-ipp"
type = "tcp"
localIP = "192.168.1.50"
localPort = 631
remotePort = 1631
```

这只是代理条目示例，不包含你的 frpc 服务器和鉴权配置。frpc 需运行在能访问打印机的局域网设备上，设备与打印机都需在线。现有 FRP 如已映射无需重复配置，插件填写它实际提供的 HTTP 访问入口和 `/ipp/print` 路径即可。

**不能把无鉴权 IPP 端口裸露到公网。** FRP token 只保护隧道连接，不能阻止别人访问公开映射端口。应让 frps 打印端口仅绑定内部/回环地址，或用防火墙仅放行平台的可信来源；也可使用已有受限私网隧道。插件不会自动配置 FRP、绑定地址或防火墙。HTTP 只能用于可信内部链路，跨不可信网络应提供有效证书的 HTTPS 入口。

Docker 的 `127.0.0.1` 是容器自身，不是 VPS 宿主机。填写容器能访问的宿主机私网地址或已有网关，并确保防火墙放行该容器来源。若平台配置了 HTTP 代理，IPP 请求也走平台代理；代理所在设备也必须能访问这个入口。远端代理无法访问 VPS 内部入口时，需要调整现有网络或平台代理设置，插件不会自行绕过代理或修改平台。

## 2. 配置 Windows 打印端

只有选择“Windows 电脑打印端”时才需要本节。填写设备 ID（默认 `home-printer`），生成电脑端连接密钥，刷新配置页用眼睛读取，再复制到电脑端。至少 32 个无空格 ASCII 字符，不能使用平台管理员密码。

将插件包中的整个 [`agent`](agent/README.md) 目录复制到连接打印机的电脑，按 [Windows 打印端说明](agent/README.md) 安装依赖、填写 `config.json` 并运行。

电脑端与插件的 `device_id` / 密钥必须一致；`allowed_printers` 填写 Windows 中的完整打印机名称。插件“默认目标打印机”留空时使用电脑端选出的默认打印机；如填写，必须在电脑端允许列表中。

接收端的 `--list-printers` 只读打印机列表，`--check` 只检查依赖、权限、握手，不打印。`--once` 可能实际打印一个已确认任务，不要当作只读测试。

默认只接受 HTTPS 且校验证书，不跟随跳转，不使用电脑的环境代理。反代必须直接转发这些地址，不能跳到登录页：

```text
POST https://你的平台域名/api/plugin/remote_print/agent
GET  https://你的平台域名/api/plugin/remote_print/agent_file
```

每个设备只能运行一个接收端，不能复制设备密钥到另一台电脑并行运行。不要删除、修改或回退电脑端的 `journal.json`，否则会破坏防重复提交的依据。平台同一队列也不能多进程/多容器共享同一个数据目录。

## 3. Telegram 使用

先连接平台 Bot，在允许列表填写数字用户 ID。插件使用平台为它绑定的 Telegram 渠道，未绑定时读取平台默认 Bot；无需插件再填 Bot Token。给这个 Bot 私聊发 PDF 或图片，会得到任务 ID 和状态。

Bot 启动时离线、断线恢复、更换客户端或平台绑定时，插件每 10 秒检查并重新接入，不需要手动重载。不可用或停用的绑定不会改接其他 Bot；切换绑定后旧 Bot 的消息不再接受。

```text
/print 任务ID
/print 任务ID 2
/print 任务ID 2 打印机完整名称
/print_cancel 任务ID
/print_jobs
/printers
```

也可发送中文命令：“打印 任务ID”“取消 任务ID”“任务”“打印机”“帮助”。只允许操作自己创建的任务。只有 Windows 模式可以在命令中指定打印机名称；IPP 使用管理员配置的固定打印目标。需要图片原始分辨率时，请作为文件发送，避免 Telegram 压缩图片。

## 4. 企业微信自建应用

在**平台系统设置 → 通知渠道**配置企业微信自建应用的 CorpID、AgentID、Secret，以及已有的企业微信 API 中转地址（如使用）。插件直接读取这些设置，不另存应用 Secret。多个自建应用时，在平台通知路由中为“远程打印”绑定使用的应用，或指定一个默认应用；不随机选择。群机器人不能接收文件。

在平台该企业微信渠道中开启“消息回调”，填写回调 Token 和 EncodingAESKey（配置字段为 `callback_token`、`callback_aes_key`），并授权允许操作的成员。插件直接读取这些设置，不生成、回写或另存密钥；缺少任一项或平台关闭回调时停止接收，不使用旧插件密钥兜底。需要查看密钥时，在平台渠道中点眼睛；插件按钮、状态和日志不展示密钥。平台替换密钥后插件立即使用新值。

在插件填写允许打印的**成员 UserID**，不是昵称或手机号；成员还必须在平台回调的授权名单中，两处都允许才接收。平台名单用 `|` 分隔，插件名单每行一个或逗号分隔。升级前若使用了 0.0.3 插件生成的密钥，请先将那组值填入平台，便可保留企微后台原来的密钥；旧插件密钥记录不会自动删除，也不再使用。

插件校验签名、AES 密文、企业 ID、应用 ID、时间戳和成员身份，不支持未签名明文回调。

企业微信后台“接收消息”填写：

```text
https://你的平台域名/api/plugin/remote_print/wecom
```

如果反代位于子路径，请加上子路径；配置页“查看企业微信接收配置”提供打印回调地址。Token / EncodingAESKey 与平台渠道填写的一致。配置 URL 验证时可以关闭插件“接收远程打印任务”，但需开启平台消息回调。

**打印文件需使用上述插件 URL，不使用平台的 `/api/wecom/callback/渠道ID`。** 当前平台统一回调只处理文字指令，会忽略图片和文件。企微每个应用只有一个接收 URL；使用打印回调后，该应用不经过平台文字指令回调，需要两类功能时使用不同自建应用。

应用可见范围需包含允许成员，按企微后台要求配置服务器出口可信 IP。成员在**自建应用会话**中发送文件/图片后，再发送“打印 任务ID”确认；“任务”“打印机”“取消 任务ID”与 Telegram 一致。回调快速确认，下载、打印与消息回执在后台处理。回执只发给原始上传人，不使用平台渠道的 `@all` 群发目标。切换应用不会把旧任务回执发送到其他应用。企业微信应用主动发送消息没有配置好时，任务状态仍保存，可在管理员“查看最近打印任务”中查询。

媒体只从平台配置的企业微信 API 的固定 `media/get` 接口获取，不接受用户输入的下载 URL。下载使用平台的有大小上限流式服务，该服务内部会跟随媒体重定向。

## 状态、取消与恢复

| 状态 | 含义 |
| --- | --- |
| 等待确认 | 已收到合法文件，未授权打印 |
| 等待打印 | 已确认，等待 IPP 提交或电脑端领取 |
| 正在准备打印 | 检查设备能力、验证文件并转换图片；此时可取消 |
| 正在提交打印 | 已持久保存一次性提交许可；不能保证远程取消 |
| 已提交打印队列 | 打印机或 Windows 打印系统接受了任务，**不代表纸张已经打印完成** |
| 失败 | 未能完成任务；不会自动重打，请检查后重新发文件 |
| 结果待核查 | 网络/重启/提交异常，无法确定是否已经出纸；不会自动重打 |

领取准备超过 5 分钟或平台在准备阶段重启时，任务结束为失败，不再重复授权同一任务。提交后超过 10 分钟未收到回执，任务标记为待核查，迟到的有效回执仍可确认结果。打印端重启只补报已有结果；有歧义时停止该任务的重打，其他新任务仍可正常执行。

取消仅作用于尚未开始提交的任务，不控制已经交给打印机或 Windows 的打印队列。卡纸、缺纸、打印机断线及已提交任务的取消，请在打印机或 Windows 打印队列上处理。IPP 提交超时、回执损坏、连接中断或提交时停用插件，一律标记待核查，不自动重试。切换模式、设备或 IPP 地址不会把旧排队任务改投新的打印机，请重新发送文件。

待核查任务也占活动数量，防止故障任务无限堆积。先检查打印队列和实际出纸，再在管理页点“待核查任务归档（不重打）”解除容量占用；该按钮不重打，也不取消打印机中的任务。清理按钮只删除已结束任务的本插件文件，保留任务记录。已结束文件超过保留时间自动删除；未及时确认/打印的排队任务到期取消。

不要启用自动打印后允许陌生用户上传文件。文件大小/页数/像素限制不能代替 PDF 解码器的进程级安全沙箱，本版仅适合授权的可信用户。
