# NextFind 助手

## 奈飞榜单

全球、国家榜单与富元数据页面均使用平台 HTTP 服务，继承平台配置的代理，无需在插件里重复设置。代理连接失败不会回退直连；未设置平台代理时遵循平台 HTTP 服务的默认网络行为。

抓取失败会显示 HTTP 状态码、代理错误或超时原因，不将失败、空响应或解析错误当作成功榜单缓存。更新到 2.2.1 后会重新抓取旧缓存；成功榜单仍按周缓存，避免重复请求。

## 猫眼榜单

电影票房榜仍使用平台 HTTP 服务。网播热度榜使用平台配置的浏览器，在同一网页会话读取猫眼当前接口；由猫眼网页正常生成请求签名，不再请求已返回 403 的旧接口，也不将 Cookie 拷贝到独立 HTTP 请求中重放。无需新增插件配置，保留原有媒体类型、视频平台和榜单数量选择。

浏览器启动、页面加载和榜单读取有统一时间上限，失败会在日志和本轮通知中明确显示，不当作正常空榜单。缺集检查仍优先执行，猫眼失败不阻止已确认的缺集结果保存。

## 本地缺集自动订阅

在配置页的「本地缺集」单独填写 Emby 服务地址、Emby API Key 和 TMDB 密钥，保存后测试连接，再开启「本地缺集自动订阅」。支持反代域名与带 `/emby` 的地址；Emby API Key 需能读取完整剧集库。TMDB 支持 API Key 和 API Read Access Token。

插件完整读取 Emby 剧集与单集，使用剧集的 TMDB ID 对比 TMDB 各普通季的已播集，按实际季号、集号确定缺集，包括完全缺失的已播季。多版本与多集文件合并核对，不按总集数猜测，也不调用 AI 或 NextFind 的本地缺集接口。

默认播出缓冲 1 天，按北京时间检查截至昨天已播出的集。可设置 0～30 天；未来集、播出日期不明确的集、电影、特别篇、缺少 TMDB ID 或季集号不明确的剧集不会自动订阅。Emby 使用创建时间优先排序、每页请求最多 5000 条；服务器返回较小页时继续读取。重复编号、总数变化、分页失败或不完整时整轮不新增缺集订阅，并显示“扫描未完成”，不将它当作缺 0 集；某部剧的 TMDB 查询失败只跳过该剧。

检查后与 NextFind 活跃订阅按媒体类型和 TMDB ID 去重，一次处理全部未订阅的缺集剧集，不设置新增上限。「订阅历史」显示上次缺集检查与新增统计，运行日志显示具体缺季、缺集。

缺集检查先于猫眼浏览器准备和榜单订阅执行。TMDB 季详情按每批最多 20 季获取，成功完整校验后才将季号、集号与播出日期缓存到插件自己的存储中；不缓存 Emby 库存或缺集结论，每轮仍实时读取完整媒体库，并重新应用当前播出缓冲日期。

Emby 每页请求 5000 条，不读取无关的图片和用户观看状态；若服务端实际返回较小页，仍按实际条数继续读取并检查总数和重复编号。服务器最多同时核对 12 部剧，Windows 保持 4 部以避免平台同步 TLS 初始化造成握手阻塞；每秒最多启动 10 次请求，收到 HTTP 429 后遵守服务端等待时间，不盲目重试。首次大库扫描需要建立缓存，耗时取决于网络和平台 HTTP 请求开销，不能保证所有环境都在几分钟内完成；已有有效缓存时会显著加快。首部核对结果立即显示，之后按分钟汇报进度，并非停留在第一部。

在播剧详情和可能更新的季缓存 6 小时，已结束剧详情缓存 24 小时，确认已播完超过 30 天的历史季缓存 7 天。缓存容量有上限，失败响应、资料不完整的季不会当作有效缓存；读取时校验内容摘要，损坏、旧格式或过期的缓存重新在线获取。

整轮最多运行 30 分钟，其中缺集扫描最多 25 分钟。首次大库核对可能分多轮完成：达到上限会明确显示未核对数量，已完整核对的缺集候选仍正常处理，下轮优先尚未完成的剧集，不会反复从同一批开头重跑。已完成剧集随后仍会按本轮库存重新核对；进度标记不是永久跳过名单。更新、重载或停用会停止后续请求，已确认新增的订阅和核对进度保留。

「自动补缺集」是独立功能：根据 NextFind 已有剧集订阅的入库进度触发补缺搜索，遵循配置的每轮补缺上限。只开启缺集自动订阅不会自动开启补缺搜索。

Emby 和 TMDB 仅进行读取，不修改媒体库。连接测试使用已保存配置，不新增订阅；密钥默认隐藏，点眼睛可查看。运行与扫描停止后不会再提交后续订阅；已经发送的请求仍可能由 NextFind 完成处理。
