# 账号登录与通知配置

本章适用于 AWBotNest V2。先把“用哪个账号执行插件”和“把通知发到哪里”分开理解，配置会简单很多。

> 本章截图使用演示数据。不要把 Bot Token、API_HASH、手机号、验证码、登录会话或企业微信 Secret 发到群里。

## 1. 先分清这几种账号和凭据

| 名称 | 是什么 | 在哪里使用 |
| --- | --- | --- |
| 管理员账号 | 登录 AWBotNest 网页的用户名和密码 | 系统登录页面，与 Telegram 无关 |
| Telegram 用户账号 | 你平时在 Telegram 手机 App 中使用的账号，也常被叫作“人形账号” | 「账号管理」登录；供需要用户身份的插件使用 |
| Telegram Bot | 通过 BotFather 创建的机器人，不是手机号账号 | 「系统设置 → 通知渠道」添加；用于 Bot 插件、发送通知 |
| API_ID / API_HASH | Telegram 应用凭据，一组必须配套 | 「系统设置 → 账号与凭据 → Telegram 凭据」 |
| Bot Token | 某一个机器人的密钥 | Telegram 通知渠道的「Bot Token」 |
| Chat ID | 通知接收人的用户、群组或频道标识 | Telegram 通知渠道的「Chat ID（可选）」 |

API_ID 不是你的 Telegram 用户 ID；API_HASH 不是 Bot Token；管理员密码也不是 Telegram 两步验证密码。它们不能互相替代。

如果只使用独立运行或企业微信插件，不需要为了进入系统而强行配置 Telegram。是否需要 Telegram，要看插件说明。

## 2. 配置 Telegram 应用凭据

1. 用自己的 Telegram 账号登录 [my.telegram.org](https://my.telegram.org)。
2. 进入 **API development tools**，创建应用并取得同一应用下的 `api_id` 和 `api_hash`。Telegram 页面字段以实际显示为准。
3. 打开 AWBotNest「系统设置 → 账号与凭据」，找到「Telegram 凭据」。
4. 在 `API_ID` 填数字，在 `API_HASH` 填对应字符串。不要带多余空格或引号。
5. 点击「保存 Telegram 凭据」，按页面提示重启系统。
6. 重启后进入「账号管理」，开始登录。

**正常现象：** 不再显示“Telegram 用户账号功能尚未启用”，可以看到「+ 登录新账号」。

**如果出现 `ApiIdInvalidError` 或 `The api_id/api_hash combination is invalid`：** Telegram 不认可这一对凭据。回到上述页面核对，不是验证码输错，也不是换个插件就能解决。改完后要保存并重启，不能只在输入框里改一下。

## 3. 登录 Telegram 用户账号

![账号管理演示界面](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/accounts.jpg)

1. 打开「账号管理」，点击「+ 登录新账号」。
2. 填写「本地账号名称（英文，自定义）」，例如 `personal_account`。只使用英文字母、数字和下划线；这是系统保存会话时使用的名称，不是 Telegram 昵称。
3. 在「手机号（带国家码）」填写完整号码，例如中国号码前加 `+86`。这里只是格式说明，不要照抄演示号码。
4. 点击「发送验证码」。到 Telegram 官方客户端查看验证码，是否提供短信等方式由 Telegram 决定。
5. 填写收到的验证码，点击「确认」。不要频繁重复点击发送。
6. 账号启用了两步验证时，继续填写 Telegram 的两步验证密码。没有开启的账号会跳过这一步。
7. 出现“登录成功并已上线”后点击「完成」。

登录步骤需要在 10 分钟内完成。流程过期时重新发送验证码，不要一直提交旧验证码。

![登录账号表单，手机号为界面内置格式示例](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/account-login.jpg)

账号卡片会显示头像、名称、用户 ID 和在线状态。已启用且适用该账号的插件会随账号上线恢复运行；插件自身仍需要正确配置。

### 上线、下线和删除有什么区别？

- **下线：** 断开该用户账号，不等于退出网页，也不等于删除登录状态。
- **上线：** 使用已保存的登录状态恢复连接；会话失效时仍需重新登录。
- **删除：** 断开连接、删除该账号保存的登录信息并从配置移除。操作不可恢复，下次需要重新登录。

Telegram 登录状态保存在部署目录映射的 `sessions/` 中。不要公开、发给陌生人或提交到 Git。迁移时参照 [备份与维护](Maintenance)。

### 网络断了，账号会怎样？

系统会尝试恢复网络中断的连接，并恢复账号相关服务。正常重连不需要重新输入验证码。但以下情况不能靠重连解决：

- Telegram 已撤销该会话，或账号主动在官方客户端结束了这个会话；
- API_ID/API_HASH 不正确；
- 账号被限制、登录被拒绝或两步验证未完成；
- 代理一直不可用。

手动点「下线」是管理员明确要求停止，不应期待它自己重新上线。持续离线时先查看「运行日志」，不要反复删除账号。

## 4. 设置网络与代理

入口：「系统设置 → 运行环境 → 运行代理」。

如果服务器不能直接访问 Telegram，可以启用代理并填入**服务器或容器实际可访问**的代理地址。支持 `http`、`socks4`、`socks5`。需要认证时的格式为：

```text
socks5://用户名:密码@代理主机:端口
```

这只是格式，不是可直接使用的代理。保存前可点击「测试代理」；保存后基础连接设置按页面提示重启生效。

特别注意：

- Docker **bridge 模式**中，容器里的 `127.0.0.1` 指容器自己，不等于宿主机；host 模式共用宿主机网络。代理装在宿主机时，地址必须按你的网络模式设置，见 [安装部署](Installation)。
- 系统代理会供 Telegram、系统 HTTP 请求、浏览器服务以及依赖下载使用。插件如果自己写了独立网络代码或显式指定代理，仍由插件决定。
- 企业微信渠道里的「代理地址（可选）」是企业微信 API **转发服务根地址**，不是上面这种 SOCKS 代理，不要混填。
- 不要在含代理用户名和密码的报错截图中保留完整地址。

## 5. 添加 Telegram 通知 Bot

![通知渠道演示界面](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/notifications.jpg)

已有渠道需要编辑时，点击卡片下半部分的类型名称或图标；右上角的 × 是删除，不是编辑。

1. 在 Telegram 找到经过核对的 [@BotFather](https://t.me/BotFather)，按提示创建自己的 Bot，取得 Token。
2. 用准备接收通知的 Telegram 用户账号打开这个 Bot，先点 **Start / 启动**，或发送 `/start`。Bot 不能主动向从未启动过它的用户发私信。
3. 打开「系统设置 → 通知渠道」，点击渠道区下方的 **+**，选择「Telegram」。
4. 填写名称、Bot Token，保持「启用」。需要作为默认通知渠道时勾选「设为默认」。
5. 建议明确填写 Chat ID，避免多账号时误解接收人。发送到群组或频道时，先添加 Bot，并给它必要的发言权限。
6. 按需勾选「通知插件」，点击「确认」。

Chat ID 留空时，系统先使用全局默认 Chat ID；仍未设置时尝试使用配置中的首个用户账号作为接收人。为了让通知不依赖用户账号在线状态，推荐填明确的接收目标。

**用户账号离线和 Bot 通知是两条不同链路。** Bot Token、接收人和网络都有效时，不应因为用户账号暂时离线就要求重启整个系统才能收到通知。若只在用户账号在线时能收到，优先核对 Chat ID、Bot 是否已被启动，以及运行日志中的投递错误。

## 6. 默认渠道和“推送路由”

「推送路由」就是给插件挑选通知目的地，不是给插件选择执行账号。

例如：一个使用 Telegram 用户账号执行的签到插件，可以把通知发给企业微信；它仍然使用原来的 Telegram 用户账号执行签到。

1. 先创建并启用需要的渠道。
2. 在「系统设置 → 通知渠道 → 推送路由」搜索插件名称或 ID。
3. 勾选该插件要使用的渠道，可选择多个。这里的修改会立即生效。
4. 没有单独选择渠道时，使用默认渠道。默认渠道只能设置一个。

系统会分别尝试多个指定渠道，单个渠道失败不应阻止其他渠道投递。若所有渠道都不可用，系统可能尝试在线主用户账号的“收藏夹”保底投递；这不代表配置好的通知渠道已经正常。

> 系统能提供通知接口，不代表所有插件都会主动发通知。插件必须实际调用通知能力。插件的 Telegram 事件、命令和通知目的地也不是同一个概念。

### 系统更新通知

「通知渠道」页的「系统更新通知」默认打开。发现系统新版本时，会把版本及更新内容发送到**默认 Telegram Bot**，不是任意默认企业微信或 Bark 渠道。确保默认 Bot 和接收人已配置。系统更新方法见 [备份与维护](Maintenance)。

## 7. 企业微信：只收通知的配置

当前界面使用**企业微信自建应用**：

1. 在企业微信管理后台创建或打开自建应用，记录「企业 ID」「AgentID」「Secret」。
2. 确保接收成员在应用可见范围内；企业微信要求可信 IP 等设置时，按后台提示配置你的服务器出口 IP。
3. 在系统「通知渠道」点击 **+ → 企业微信**。
4. 填写「企业ID」「应用AgentId」「应用Secret」。
5. 「接收成员（可选）」不填时默认 `@all`；指定成员时填写通讯录 **UserID**，多个用 `|` 分隔，例如 `zhangsan|lisi`。
6. 不使用 API 转发服务时，「代理地址（可选）」留空。
7. 只接收通知时，**不用打开“消息回调”**，也不需要 Token 和 EncodingAESKey。
8. 保存渠道，再关联要接收通知的插件。

**正常现象：** 插件产生通知后，指定成员可在企业微信应用中收到消息。

![企业微信自建应用配置（演示数据）](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/wecom-channel.jpg)

群机器人 Webhook 和自建应用不是同一种接入方式。后端兼容已有群机器人通知配置，但当前新增渠道表单是自建应用字段；群机器人地址也不能用来开启自建应用消息回调。

## 8. 企业微信：接收指令、图片和文件

需要从企业微信向系统或插件发消息时，才配置回调。它是在第 7 节通知配置之上增加的能力。

### 8.1 先准备能被企业微信访问的地址

回调地址的格式是：

```text
https://你的系统域名/api/wecom/callback/渠道ID
```

复制渠道表单生成的实际 URL，不要把这里的“渠道ID”原样填写。

- 回调和网页/API 使用**同一个 Web 服务**，没有额外独立的回调端口。
- 默认部署内部网页端口是 `18001`；你的 Docker 映射端口、安装脚本选项或反向代理可以改变外部访问方式。
- 公网通过 HTTPS 域名访问时，通常填写域名的 `443` 入口，由反向代理转发到系统，不是强行给 URL 添加 `:18001`。
- 页面按浏览器当前访问地址生成 URL。用 `127.0.0.1` 或局域网 IP 打开网页时，复制出来的地址通常不能被企业微信服务器访问。先通过正确的公网域名打开系统，再复制。

### 8.2 两边填写同一组回调参数

1. 打开该企业微信通知渠道，勾选「消息回调」。
2. 填写「回调 Token」「EncodingAESKey」。它们来自企业微信自建应用的 **API 接收消息**配置，可按企业微信后台提供的方式生成。
3. 在「允许操作的成员」填通讯录 UserID，多个用 `|` 分隔。不能为空，不支持用 `@all` 放行所有成员。
4. 在「通知插件」中只勾选允许此渠道访问的插件。回调成员权限和插件范围应尽量小。
5. 点击「确认」先保存，然后重新打开渠道复制「回调 URL」。
6. 到企业微信自建应用「接收消息 / 设置 API 接收」中填写同一 URL、Token 和 EncodingAESKey，完成地址验证并保存。

`EncodingAESKey` 必须为企业微信要求的 **43 位** Base64 字符。应用 Secret、回调 Token、EncodingAESKey、开放 API Key 和 Webhook Secret 是不同凭据，不要互相代替。

![企业微信回调参数（演示数据）](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/wecom-callback.jpg)

*截图中的 `127.0.0.1:18201` 仅为本地演示地址，不能拿去填写企业微信回调；请使用自己可公网访问的 HTTPS 域名。*

### 8.3 如何确认接通？

先用已允许的成员向应用发送：

```text
/帮助
/状态
/插件
```

运行插件已注册的动作时使用：

```text
/运行 插件ID 动作名
```

有参数的动作可在后面附 JSON 对象，具体名称和参数以插件说明为准。系统不会把 Telegram 专用命令自动变成企业微信命令。

图片、文件、菜单按钮事件等可经统一回调交给已适配的插件。需要同时满足：插件已启用、已关联此通知渠道，并且开发者注册了对应消息处理器。仅仅开启回调，不会让所有插件自动支持打印或图片识别。开发接口见 [插件开发](Plugin-Development)。

系统会验签、解密、检查企业/应用身份及成员权限，并对消息重试去重。关闭「消息回调」后，单向通知仍可继续使用。系统停止时排队中的回调任务会取消，不会保证在下次启动后自动重跑。

## 9. Bark 通知

1. 在 iPhone 安装 Bark，打开 App 获取自己的服务器地址和设备密钥。
2. 「系统设置 → 通知渠道」点击 **+ → Bark**。
3. 填「服务器地址」，使用官方服务时通常为 `https://api.day.app`；自建时填写自己的地址。
4. 将 App 的密钥填入「设备密钥」，不是填整个推送 URL 到密钥框。
5. 保持启用，按需设为默认或关联插件，点击「确认」。

Bark 只是通知接收渠道，不会替代 Telegram 用户账号，也不会接收系统的企业微信指令。

## 10. Webhook 入站和出站不要混淆

- **入站：外部程序 → AWBotNest。** 在「系统设置 → 开放接口 → Webhook 入站」设置独立密钥，复制地址。该接口把外部文字交给系统通知服务，再发往通知渠道。
- **出站：AWBotNest → 外部程序。** 后端支持 Webhook 通知渠道，但当前网页的新增菜单仅有 Telegram、企业微信和 Bark，没有通用 Webhook 新增表单。不要在网页中寻找并不存在的按钮。

入站地址形式为 `/api/v1/webhook?apikey=你的Webhook密钥`。密钥在 URL 中，不能公开截图或直接贴到公共 issue。它与开放 API Key 不同。请求格式及插件 Webhook 的区别见 [开放 API](Open-API)。

## 11. 常见问题速查

| 现象 | 先检查什么 |
| --- | --- |
| 验证码一直收不到 | API_ID/API_HASH 是否配套且重启生效；服务器或容器的 Telegram 网络；Telegram 官方客户端中的验证码消息 |
| 提示验证码过期 | 重新从发送验证码开始，不要继续提交旧码；登录流程等待过久会过期 |
| 用户账号上线了，插件没反应 | 插件是否启用、作用域是否需要此账号、是否有账号选择和插件专属配置；查看插件日志 |
| Bot 私信失败 | 接收人是否先启动过 Bot；Chat ID 是否正确；是否被屏蔽；网络是否正常 |
| 群组/频道收不到通知 | Bot 是否在目标中、是否有发言权限，Chat ID 是否为完整目标 ID |
| 企业微信 URL 验证失败 | 公网 HTTPS、反向代理路由、渠道是否已保存且启用、URL/Token/AESKey 是否与该渠道一致 |
| 企业微信能收到通知但指令无回复 | 消息回调是否开启；成员 UserID 是否在允许列表；插件是否关联并提供对应动作/处理器 |
| 一直显示 `********` | 这是已保存敏感值的掩码，不是实际密码；不要手动把八个星号当作密钥复制到别处 |

遇到问题请先看 [故障排查](Troubleshooting)，提供版本、部署方式、问题时间和脱敏日志。不要提供密钥或登录会话。
