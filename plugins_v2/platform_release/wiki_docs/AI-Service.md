# AI 服务：从接入到排错

系统提供统一的 AI 接口。使用该接口的插件共享系统中配置的服务商和模型，不需要在每个插件中重复填写服务商密钥。某些旧插件可能仍有自己的 AI 配置，以插件说明为准。

本章说明网页中的实际配置顺序：**服务商 → 模型库 → 模型分工 → 测试 → 插件权限**。

![AI 调用概览（演示数据）](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/ai-service.jpg)

## 1. 配置前先准备三样东西

| 项目 | 含义 | 示例或注意事项 |
| --- | --- | --- |
| 服务地址 | 供应商提供的 API 地址，不是它的官网首页 | OpenAI 兼容服务常见形态为 `https://服务域名/v1`，以供应商文档为准 |
| API Key | 调用此服务的密钥 | 从供应商控制台获取；和系统开放 API Key 不是一回事 |
| 真实模型名 | 供应商接受的模型 ID | 必须完全匹配供应商实际提供的名称，不能只填宣传名或自己起的别名 |

另外确认服务账户有额度、允许调用该模型，以及 AWBotNest 所在服务器能访问该服务。

> 测试也是真实请求，可能计费。不要把 API Key、包含密钥的 URL 或真实私密对话贴到公开问题中。

## 2. 添加 AI 服务商

1. 打开「系统设置 → AI 服务」。
2. 在「AI 服务商」点击「+ 添加服务」。已有默认项时，也可以直接编辑。
3. 保持该服务「已启用」。
4. 填「显示名称」，例如“主要文字服务”。这只是方便自己辨认。
5. 填「服务地址」。优先使用供应商文档给出的 API 根地址；不要填聊天网页地址、登录页面或充值页面。
6. 在「接口格式」先选「自动识别」，不确定时不要随意固定协议。
7. 填 API Key。当前系统调用要求此项非空，不能只填掩码 `********`。云端服务使用供应商发放的真实 Key；自建免密服务也不能直接留空，需先确认它的兼容接入方式。
8. 点击「读取模型列表」。

**正常现象：** 提示已读取若干模型，并出现「已读取的模型」选择区。

“读取模型成功”只说明能列出模型，不代表这个 Key 有权调用列表中的每一个模型。部分供应商不提供模型列表接口，仍可按第 3 节手动添加。

![AI 服务商与模型库配置（演示数据）](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/ai-provider.jpg)

### 接口格式选什么？

| 选项 | 适用情况 |
| --- | --- |
| 自动识别 | 不确定供应商实际支持哪一种；系统调用时尝试可用协议并记住成功结果 |
| OpenAI Chat Completions | 供应商明确要求 `/chat/completions` |
| OpenAI Responses | 供应商明确要求 `/responses` |
| Anthropic Messages | 供应商明确要求 `/messages`，使用 Anthropic 消息格式 |

这些是**请求和响应的格式**，不是模型质量档位。模型名以 `gpt` 开头，也不能证明某个第三方服务一定开放 Chat Completions。

固定一种格式后，系统不再为它自动尝试其他文字协议。只有在供应商文档明确、或自动识别仍失败时，才按实际接口固定。生图使用图片接口，不能仅凭“生图成功”判断文字协议也正确。

## 3. 把模型加入“模型库”

### 方法一：从已读取列表添加

1. 展开「已读取的模型」。
2. 搜索想使用的真实模型名并勾选。
3. 点击「添加所选模型」。
4. 在模型库中展开新模型，设置名称、调用别名和能力。

### 方法二：手动添加

读取列表失败但供应商提供了模型名称时，点击「+ 手动添加模型」：

- **显示名称：** 网页中便于辨认的名字，例如“快速问答”。
- **插件调用别名：** 插件请求该模型时可用的简短名称，例如 `fast`。不要为不同模型设置容易混淆的别名。
- **所属服务：** 选择真正提供这个模型的服务商。
- **真实模型名：** 填供应商支持的精确 ID。
- **模型能力：** 按供应商实际能力勾选，不能靠勾选把纯文字模型变成识图或生图模型。
- **已启用：** 关闭后不会作为可用模型供选择。

三个能力的区别：

| 能力 | 用来做什么 | 不代表什么 |
| --- | --- | --- |
| 文字模型 | 总结、改写、问答、结构化处理 | 不一定能读取图片 |
| 视觉模型 | 识别截图、图片、视觉内容 | 能看图不代表能生成图片 |
| 生图模型 | 根据描述生成图片 | 生图能用不代表文字问答接口能用 |

支持多个能力的同一模型可以勾选多个，但仍应分别测试。模型较多时可用模型库的搜索、服务商/能力/状态筛选、折叠编辑和分页，不需要一次展开全部。

## 4. 在“模型分工”设置默认和备用模型

添加进模型库还没结束：需要告诉系统哪项能力默认用谁。

1. 向下找到「模型分工」。
2. 在「文字模型 → 默认模型」选择刚才添加的文字模型。
3. 需要识图时，给「视觉模型」指定支持视觉的模型。
4. 需要生图时，给「生图模型」指定真正支持图片生成的模型。
5. 有可靠备用服务时，可以设置「备用模型（可空）」。不需要就保持“不使用备用模型”。
6. 保存 AI 设置。AI 设置保存后立即生效，不需要为了换模型重启系统。

没有显示在下拉框中的模型，先检查：模型和所属服务是否启用、真实模型名是否为空、服务地址是否有效、该能力是否已勾选。

默认模型供未指定模型的调用使用。插件如果明确请求某个模型或别名，或管理员为它指定了单独模型，就不一定使用全局默认模型。备用模型也不能解决所有问题，例如两个模型都依赖同一个已经断网的供应商。

## 5. 分别点击“测试”

1. 在「模型分工」点击相应能力右侧的「测试」。
2. 有未保存修改时，测试会先保存；保存失败就不会继续测试。
3. 等待结果。生图通常比文字慢，不要因为几秒没有返回就连续点击。
4. 查看成功提示，然后回到页面上方「最近调用」核对实际服务、模型、协议、耗时和 Token。

**正常现象：** 测试提示成功；最近调用新增成功记录；成功次数增加。生图测试会实际生成图片，可能产生服务商费用。

文字测试成功，不保证所有插件的大文本、图片或特殊参数也都能成功。它证明基础接入可用；插件自己的输入和功能仍需按插件说明验证。

## 6. 为插件设置 AI 权限和单独模型

在「插件 AI 设置」中：

1. 找到要配置的插件。
2. 使用「允许 AI」控制此插件是否允许调用系统 AI 服务。
3. 按需勾选文字、视觉、生图能力。
4. 对每项能力选择「跟随默认设置」或单独指定模型。
5. 保存设置。

例如：签到识别插件只允许视觉，消息改写插件只允许文字。无需为了允许一种能力而把所有能力都打开。

没有出现某个插件时，不一定是故障。系统会识别使用系统 AI 能力的插件；未适配、尚未安装或自己直接调用第三方 API 的插件，不一定出现在这里。

系统服务不会把供应商密钥作为正常插件 AI 接口的返回值。但 Python 插件本身属于在系统中执行的代码，不能把这个设计当成不可信插件的安全沙箱；安装来源仍需可信。

## 7. 调用次数、Token 和最近记录怎么看？

### 调用概览

- **总调用、成功、失败：** 系统记录的调用统计。
- **进行中：** 目前尚未结束的调用。
- **输入/输出/总 Token：** 以供应商响应中返回的用量为准。

一次操作如果涉及协议尝试、备用模型或插件的多次调用，可能留下多条尝试记录；不要把每次点按钮与每一条 HTTP 尝试强行一一对应。

Token 不是人民币，也不是精确的汉字数。供应商不返回用量时，系统可能没有可统计的 Token；`0 Token` 不等于免费，账单以供应商为准。图片服务也可能有单独的图片计费规则。

### 最近调用

保留最近 **200 次**，初次显示 **20 条**，可以继续加载。记录包括：

- 来源：系统或具体插件名称；
- 服务、模型、能力和实际使用的协议；
- 成功/失败、耗时、Token；
- 失败分类及错误摘要。

可以筛选成功/失败，或点击「刷新」。下方「插件调用汇总」便于定位哪个插件调用较多、失败较多。点击「清空」只清空最近调用和插件聚合明细，**累计次数与 Token 统计仍保留**。

这里的耗时是系统观察到的整次尝试时间，可能包含等待并发名额、网络和供应商生成等过程，不能直接当成纯模型生成速度。

## 8. 调用保护怎么设置？

「调用保护」提供：

- **文字与识图超时（秒）：** 默认 60 秒。
- **生图超时（秒）：** 默认 300 秒。
- **最多同时调用：** 默认 3，可在界面范围内调整；超过上限的请求会等待。

建议先用默认值。服务器小、服务商限制严格时可降低并发；不能为了“快”无限增加并发，否则可能触发服务商限流或增加内存、连接压力。

提高超时只是多等一会儿，不会让模型本身生成得更快。真正耗时长时，先选更快模型、减少输入、避免让多个插件同时大量调用，并检查服务商与服务器网络。

## 9. 常见错误与处理顺序

| 错误/现象 | 常见原因 | 操作 |
| --- | --- | --- |
| 认证失败 / 401 | Key 错误、失效，或对应服务地址不对 | 重新核对供应商 Key 与地址，查看供应商控制台 |
| 权限被拒绝 / 403 | 账户、模型或地区权限不足 | 核对模型权限与供应商限制 |
| 模型不存在 | 真实模型名错误或此 Key 无权访问 | 按供应商实际 ID 重新填写，不要用显示名称代替 |
| 接口路径不存在 / 404 | 地址前缀、协议或版本路径不对 | 核对 `/v1` 等前缀和实际接口格式 |
| 服务商限流 / 429 | 请求过多、余额或额度限制 | 查看供应商返回说明，降低并发，等待或补充额度 |
| 接口返回 HTML / 协议不匹配 | 填成网页地址、被网关拦截，或选错协议 | 核对 API 地址和协议，检查反向代理与服务商状态 |
| `JSONDecodeError` / 响应格式异常 | 返回值不是预期 JSON，可能为空、HTML、错误页或不兼容格式 | 查看最近调用和脱敏日志；不能仅凭此断言一定是 Key 错误 |
| 请求超时 | 上游生成慢、排队、网络或代理不可达 | 小请求单独测试，对比模型，适当调超时 |
| 网络异常 | DNS、TLS、代理或供应商不可达 | 在系统运行环境检查网络；浏览器能打开官网不等于容器能调用 API |
| 插件未获准使用某能力 | 插件 AI 权限关闭，或能力未勾选 | 查看「插件 AI 设置」后保存 |
| 指定模型不存在或未启用 | 只读了模型列表，没加入模型库/分工，或模型被停用 | 按第 3、4 节补全配置 |
| 生图成功，文字失败 | 图片和文字接口、模型权限不同 | 单独测试文字，核对 Chat Completions / Responses / Messages |

排查时先完成“一个服务商、一个文字模型、一个默认分工”的最小配置，测试成功后再加备用服务和其他能力。这样比一次导入几十个模型更容易定位问题。
