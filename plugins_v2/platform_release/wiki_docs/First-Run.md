# 首次使用

本页从“已经能打开 AWBotNest 网页”开始。如果网页还打不开，先看 [安装与部署](Installation)。

## 1. 先设置管理员账号

首次打开时，页面会显示“首次使用 · 设置管理员账号”。没有统一的默认管理员密码，也不需要去别处注册网站账号。

![首次设置管理员账号](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/first-run.jpg)

1. 在“管理员用户名”填入你要用于网页登录的用户名。
2. 在“设置密码”填写密码。
3. 在“确认密码”再输入一次相同密码。
4. 点击“保存并进入”。

系统最低要求密码 4 位。公网部署不要只用 4 位密码，建议使用长度至少 12 位、不与其他网站重复的密码，并保存到密码管理器。

成功后会进入管理界面。以后打开网页，用这里设置的用户名和密码登录。

> 管理员账号只是 AWBotNest 的网页管理账号，不是 Telegram 手机号、Bot 用户名，也不是服务器 SSH 账号。不要把这些密码混填。

如果是全新部署，却已经显示普通登录页，应先确认是否误用了旧 `data` 目录，或访问到了另一个正在运行的实例。不要急着删除配置文件。

## 2. 认识常用入口

手机和电脑的导航位置不同，但页面功能对应一致。手机可从底部导航进入主要页面，设置页里的分组可以切换。

| 页面 | 什么时候用 |
| --- | --- |
| 运行概览 | 看系统资源、账号状态、插件和任务概况 |
| 插件管理 | 安装、启停、配置、更新插件，查看插件日志 |
| 账号管理 | 登录 Telegram 用户账号，查看账号在线情况 |
| 运行日志 | 看系统或插件的报错、执行结果 |
| 运行概览中的“定时任务”区域 | 查看即将执行的任务、下次执行时间和当前执行进度 |
| 系统设置 | 填凭据、通知、AI、Cookie、运行环境及备份设置 |

“系统设置”目前分为“账号与凭据”“通知渠道”“AI 服务”“Cookie 服务”“开放接口”“运行环境”“维护”。不同功能不必一次全部配置，按插件需要逐项填写即可。

## 3. 先分清 Telegram 用户账号与 Bot

| 你要做的事 | 需要配置什么 |
| --- | --- |
| 用自己的 Telegram 身份运行插件 | Telegram `API_ID`、`API_HASH`，以及手机号登录 |
| 通过 Telegram Bot 收通知或运行 Bot 插件 | Telegram `API_ID`、`API_HASH`，以及 Bot Token、通知目标等 |
| 使用不依赖 Telegram 的独立插件 | 按插件说明配置，不必为了进入网页而先登录 Telegram |

Bot 和用户账号不是互相替代的关系。插件支持哪种账号，取决于插件本身。

### 填写 API_ID 和 API_HASH

1. 打开“系统设置 → 账号与凭据”。
2. 找到“Telegram 凭据”。
3. 在 [my.telegram.org](https://my.telegram.org) 申请应用凭据。
4. 将 `API_ID` 填入对应数字输入框，将 `API_HASH` 填入对应密钥输入框。
5. 点击“保存 Telegram 凭据”。
6. 出现“部分改动需重启后才生效”时，点击“立即重启”，等待网页重新连接。

不要把 BotFather 给你的 Bot Token 填进 `API_HASH`。`API_ID` 与 `API_HASH` 必须来自同一个 Telegram 应用，否则登录会出现“组合无效”一类错误。

### 登录用户账号

到“账号管理”点击“登录新账号”，先填写英文“本地账号名称”（例如 `user_account`，用于系统内识别，不是 Telegram 用户名），再填写带国家码的手机号，发送并输入验证码；启用了 Telegram 两步验证的，还需要输入两步验证密码。

验证码可能发送到 Telegram 已登录设备，而不一定是短信。不要连续重复发送，也不要把验证码、两步验证密码发给其他人。

更详细的账号登录和 Bot 通知设置见 [账号与通知](Accounts-and-Notifications)。

## 4. 安装第一个插件

建议先装一个你明确知道用途、支持 V2 的插件，不要第一次就同时启用很多插件，出错时不容易判断来源。

1. 打开“插件管理”。
2. 切换到“插件市场”。
3. 找到目标插件，阅读其说明、账号要求和配置要求。
4. 点击“安装”，等待安装完成。
5. 回到“我的插件”。
6. 按插件要求填写配置、绑定账号或通知渠道。
7. 打开插件的启用开关。
8. 查看插件状态和日志，确认启动成功。

> 插件下载完成后默认不会自行运行；只点“安装”而没有启用，不会执行它的功能。插件来源应可信，第三方插件与系统运行在同一个环境中，不能把插件当成无权限的网页小工具。

有些插件第一次启用会安装第三方依赖，浏览器类插件还可能下载浏览器内核。此时先看日志，确认是在下载、安装还是报错，不要反复关闭、开启造成重复操作。

插件类型、账号绑定、定时规则和自检说明见 [插件管理](Plugins)。

## 5. 按需配置服务

不使用的功能可以先不填。

- **通知**：到“系统设置 → 通知渠道”添加渠道，设置默认通知目标，再发送测试消息。见 [账号与通知](Accounts-and-Notifications)。
- **AI**：到“系统设置 → AI 服务”添加服务、模型并设置模型分工。单独填一个 API Key 不等于已经完成模型设置。见 [AI 服务](AI-Service)。
- **Cookie**：到“系统设置 → Cookie 服务”配置浏览器直连或远程 CookieCloud。见 [Cookie 与浏览器](Cookies-and-Browser)。
- **代理与浏览器**：到“系统设置 → 运行环境”配置。使用 Docker bridge 时，代理地址里的 `127.0.0.1` 不是宿主机，请先看网络说明。见 [安装与部署](Installation)。
- **对外接口**：有自动化脚本需要调用时，再配置“开放接口”。不要把 API 密钥给不可信的人。见 [开放 API](Open-API)。

## 6. 保存与重启怎么判断

各功能的生效方式不同，以页面保存后的提示为准。

- 页面顶部出现未保存标记时，点击“保存设置”；切换页面、刷新或关闭网页不是保存。
- AI 与 Cookie 服务保存后可立即生效。
- Telegram 基础凭据、代理等改动可能需要重启，页面会提示。
- Bot 渠道保存后会尝试立即同步；如果提示某个 Bot 连接失败，去日志查看原因，不要把“设置已保存”等同于“账号已连接”。
- 网页中的“立即重启”用于重新加载系统设置，不会替你拉取新的 Docker 镜像。

首次接入服务时，建议“修改一项 → 保存 → 按提示重启 → 测试这一项”，成功后再继续下一项。

## 7. 第一次用好后做一次备份

到“系统设置 → 维护”，点击“下载配置包”，把 ZIP 放到安全位置。

这份配置包只包含系统设置和插件设置，不是完整数据备份；Telegram 会话、Cookie 数据、日志和插件程序不在里面。要迁移服务器或保留完整运行环境，还要备份 `data`、`sessions`、`plugins` 三个目录，操作见 [更新与维护](Maintenance)。

配置包可能包含密钥、通知凭据和管理员认证资料。不要当成普通截图或示例文件发到群里。

## 完成检查

使用前确认以下几项即可，不必追求把每个设置都填满：

- 能用自己设置的管理员账号登录。
- 所需 Telegram 账号或 Bot 已连接；不需要 Telegram 的功能可以不配。
- 插件来自可信来源，并已按说明配置和启用。
- 有通知需求时，测试消息能到达正确目标。
- 已保存配置包；重要系统另有完整目录备份。
