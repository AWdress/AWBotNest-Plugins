# 插件安装与使用

本页适用于 AWBotNest V2。系统本身负责账号、任务、通知和公共服务，具体功能由插件提供。

第一次使用建议按顺序做：安装一个插件 → 看插件说明 → 填好配置 → 选择账号与通知渠道 → 启用 → 查看日志确认结果。不要一开始同时安装、启用几十个插件，出错时不容易定位。

相关页面：[首次使用](First-Run) · [账号与通知](Accounts-and-Notifications) · [维护与更新](Maintenance) · [常见问题](Troubleshooting)

## 1. 先分清“安装”“启用”“执行”

| 操作 | 实际作用 |
| --- | --- |
| 安装 | 把插件文件下载或上传到系统中；新安装的插件不会自动运行。 |
| 配置 | 填写插件需要的业务参数，例如目标会话、网站账号或执行时间。 |
| 启用 | 载入插件，注册它的消息处理器、定时任务或网页动作。 |
| 手动执行 | 调用插件提供的某项操作，例如“测试连接”“立即签到”。不是所有插件都有此按钮。 |
| 停用 | 停止插件，取消受系统管理的后台任务，不删除插件文件和已保存配置。 |
| 重载 | 停止旧实例后重新载入，用于让更新后的代码或配置重新初始化。 |
| 删除 | 删除插件文件及系统保存的该插件配置、账号范围和通知路由；请先备份。 |

打开了插件开关，不等于业务已经成功执行。定时插件可能只注册了明天的任务；消息插件可能在等下一条消息；首次启用也可能需要下载依赖。

![我的插件界面](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/plugins.jpg)

*“我的插件”集中显示已安装的插件。截图中的插件和配置仅作演示。*

## 2. 从插件市场安装（推荐）

1. 打开「插件管理」。
2. 切换到「插件市场」。
3. 搜索插件名称，查看说明、作者、作用域、版本和更新内容。
4. 确认插件适用于 V2 后点击「安装」。
5. 回到「我的插件」找到它，先配置，再启用。
6. 打开插件日志，确认没有依赖安装失败、缺少账号或配置错误。

![插件市场（演示数据）](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/plugin-market.jpg)

*商店安装完成后，需要管理员手动开启插件。*

### 添加其他作者的仓库

在插件管理中点击「设置仓库地址」，添加额外的公开 GitHub 插件仓库。

- 内置仓库无需重复添加。
- 当前界面要求仓库名为 `AWBotNest-Plugins`，可填 `作者名/AWBotNest-Plugins`。
- V2 清单文件是仓库根目录的 `manifest_v2.json`。
- 仓库存在但商店为空，不一定是网络问题：也可能没有 V2 清单，或者插件不适用于当前系统版本。
- GitHub 访问失败、限额不足时，检查系统代理及 GitHub Token 设置。Token 不是插件运行必填项，不要随意填写别人提供的 Token。

GitHub 仓库是代码来源，不是安全认证。插件运行的是 Python 代码，可能访问网络、文件或账号；只安装自己信任的作者提供的插件。不要因为商店里能搜到，就认为系统已经检查过插件的所有行为。

## 3. 上传作者发来的插件文件

适合作者直接提供一个 `.py` 文件、临时修复版或尚未上架的插件。

1. 确认文件来自可信作者，并且是 V2 插件。
2. 打开「插件管理 → 我的插件 → 上传插件」，选择 `.py` 文件；电脑上也可拖入文件。
3. 文件必须是 UTF-8 编码，大小不能超过 2 MB。
4. 上传成功后检查配置，再启用。

当前网页上传入口和开放 API 上传接口只接收单个 `.py` 文件，不能直接上传任意 ZIP 安装包。目录形式、带 Vue 配置页的插件，优先使用作者提供的 V2 商店仓库安装。

同名文件会覆盖已有文件。替换前先停用插件并备份，不要给一个正在执行重要任务的插件直接覆盖文件。上传后也不要假定旧的运行实例已自动换成新代码，应检查状态并重载。

### 源码部署时手动放文件

了解服务器文件操作的管理员，也可以把单文件插件放入 `plugins/插件ID.py`，或把目录插件放入 `plugins/插件ID/__init__.py`。Docker 部署要放到容器映射的插件目录，而不是随意放进容器内部。

插件 ID 必须与文件名或目录名一致。不要改名后以为它仍会读取原插件的配置；不同 ID 会被当作不同插件。

## 4. 如何配置

在插件卡片的三点菜单中打开「配置」。不同插件的配置页由作者决定：有的使用系统表单，有的使用作者制作的 Vue 页面。

![插件配置示例](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/plugin-config.jpg)

*业务参数、通知渠道和生效账号是不同设置，按实际用途分别选择。*

### 插件自己的参数

先读作者填写的说明。常见参数包括网站地址、Cookie、账号、目标群组、关键词和执行周期。

- 地址是否需要以 `http://` 或 `https://` 开头，以字段说明为准。
- 不要把 Telegram 用户名当成群组 ID，也不要把 Bot Token 当成 API Hash。
- 敏感值保存后通常显示为 `********`。它是掩码，不是密码真的变成了八个星号；不要把掩码复制到其他系统当作密钥。
- 修改后使用配置页的保存按钮；不要只关闭窗口就认为已保存。
- 已启用插件保存配置时可能重新载入，正在运行的任务可能被中断。重要任务执行中尽量不要改配置。

“该插件暂无可配置项”不一定有问题，插件可能不需要配置。若作者明确要求某项配置，但页面没有此字段，先确认插件版本，再请作者检查它的 `config_schema` 或自定义配置页。系统无法自动猜出插件在代码中读取了哪些业务参数。

### 生效账号

`user`（用户账号）与 `both`（双账号）插件会显示「生效账号」。

- 选择指定账号：只对选中的 Telegram 用户账号生效。
- 选择全部账号：当前账号及之后新增的账号都可能被纳入。
- 账号需要先在「账号管理」中登录并保持在线。
- 这里不是网站账号列表，也不是通知接收人列表。

不同插件的多账号方式不一样：有的共享一个实例，有的为每个用户账号创建独立实例。不要认为多选两个账号，就一定只执行一次。

### 通知渠道

配置页中的通知渠道决定插件通过系统通知服务发送结果时走哪条渠道；可以跟随默认，也可以选择指定渠道。

先到[账号与通知](Accounts-and-Notifications)把渠道配置好并发送测试通知，再回到插件里选择。插件若自己直接调用 Telegram 发送消息，不一定使用这条通知路由；具体取决于作者实现。

通知渠道和生效账号的选项标有「立即保存」，与上方业务表单的保存不是同一个操作。

## 5. 定时任务与 Cron

只有插件主动注册的任务才会出现在系统的任务列表中。填了一段时间文本，不代表系统必然知道要定时执行；插件必须支持这项配置。

作者按规范声明的 Cron 字段，点击后会打开系统的规则编辑器。不显示编辑器时，可能是旧插件或自定义页面没有接入，不建议管理员随意修改插件代码；可把[开发接入说明](Plugin-Development#5-cron-字段与定时任务是两件事)发给作者。

![点击执行周期后展开的 Cron 编辑器](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/plugin-cron.jpg)

常见五段表达式：

```text
0 9 * * *       每天 09:00
0 */6 * * *     每 6 小时的整点
*/30 * * * *    每小时的第 0、30 分钟
```

五段顺序是“分、时、日、月、星期”；系统也接受包含秒的六段写法。以规则编辑器的说明、任务下次执行时间和插件的时区设置共同确认结果，不要只看服务器当前时钟。

查看任务时要区分：没有注册、等待执行、正在运行、执行失败。系统托管的浏览器繁忙时，新请求会排队；等待并不表示已经跳过。插件自己设置的网络超时、第三方限制或内部调度，不由这一队列统一保证。

不要反复点「立即执行」来催一个正在排队的签到任务，容易产生重复请求。对于付款、删除、发送消息等有副作用的操作尤其要谨慎。

## 6. 插件依赖为什么会下载

插件首次启用时，系统检查作者在元数据中声明的 Python 包；缺少或版本不符合时，安装到持久化目录 `data/plugin_deps`。多个依赖安装会串行处理。

- 安装界面的成功提示只表示插件文件已保存，不表示依赖已经安装完成。
- pip 下载使用系统配置的代理和镜像源。
- Python 包与浏览器内核是两类资源。安装 `cloakbrowser` 包，不代表对应 Chromium 内核已经下载。
- 浏览器、OCR、系统库等能力还有各自要求；ARM64 上的插件依赖也必须有对应架构支持。
- 所有插件共享依赖目录，不是每个插件独立虚拟环境。不要手动删除整个目录来修一个插件，否则其他插件也会受影响。

关于浏览器、CloakBrowser Key 与缓存，见[Cookie 与浏览器](Cookies-and-Browser)。关于 AI 授权及调用统计，见[AI 服务](AI-Service)。

## 7. 不工作时先看这三个地方

### 日志

在插件三点菜单中查看该插件日志，也可以到「运行日志」搜索名称和时间。

保留最早的错误和前后几条上下文，比只发一张“最后失败”的截图更有用。发给作者前遮住密码、Cookie、Token、手机号及私人聊天内容。

### 插件自检

自检会检查插件规范、已声明的 Python 依赖和加载状态。它通过了，只表示这些基础检查没有发现问题，不会替你登录网站、验证所有 Cookie 或保证每个业务接口都正常。

### 运行诊断

这里可以查看运行实例、后台任务、排队数量、熔断状态和最近事件。适合区分“没加载”“已触发但失败”“还在排队”。

有些事件提供「重新执行」。这不是只查看日志，而是真的再次执行操作；不要对已成功的发送、删除、购买等任务随意重放。

## 8. 更新、重载和卸载

插件市场发现新版本后，可单独更新，也可使用「全部更新」。更新前先读作者的更新日志；参数名称、依赖或业务逻辑可能改变。

从商店安装的插件会记录来源。手动上传或自行修改的插件，不要假定一定能被商店自动匹配更新；更不要为了追求新版本，覆盖自己尚未备份的改动。

更新后检查版本、启用状态和日志，不能只凭“下载成功”判断业务正常。运行中的任务可能受到重载影响，建议选空闲时段操作。

删除会移除插件文件及系统保存的相关配置。停用只是停止运行，删除则不是；不确定是否还要使用时，先停用即可。共享依赖、插件自行创建的数据或外部服务上的内容，不要假定会一并清除。

## 9. V1 与 V2 的兼容性

V2 使用 Telethon 插件规范。名称相同的 V1 和 V2 插件也可能是不同实现，不能直接互换；不要与 V1 共用插件目录、配置或备份。

仓库有 V1/V2 两套目录是正常情况，应安装 `manifest_v2.json` 指向的 V2 版本。迁移前先备份，按作者的迁移说明操作。
