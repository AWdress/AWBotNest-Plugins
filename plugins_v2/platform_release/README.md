# 开发者助手

AWBotNest V2 插件。用平台 Telegram **Bot** 发布最新版本并置顶，也可自定义关键词回复、根据内置手册离线简答，以及接收用户的 `#bug反馈`。回答简明列出要点，并附手册版本与 [AWBotNest Wiki](https://github.com/AWdress/AWBotNest/wiki) 来源链接；不请求 GitHub Wiki、不用 AI 作答。不使用用户账号（人形），不额外配置 Bot Token、不建立另一个 Bot Webhook 或 `getUpdates` 轮询。

由“平台发布通知”更名而来，插件 ID 仍为 `platform_release`；升级保留原有配置和发布记录。自动发布、预发行版、关键词回复、Wiki 问答、问题反馈的开关都默认关闭，按需开启并保存。

## 发布最新版本

1. 在平台配置 Telegram Bot，将 Bot 加入目标群组或频道。群组需授予发送消息、置顶权限；频道需授予发布消息和编辑消息权限（频道置顶使用编辑消息权限）。插件不重复填写 Bot Token，不要求人形账号加入目标。
2. 在“发到哪些群组或频道”中每行填一个目标，例如 `-1001234567890` 或 `@your_channel`。不接受用户私聊。示例不是默认收件人，必须换成实际目标。
3. 如果也要发布预发行版，打开“包含预发行版”。关闭时只检查正式版；开启后从正式版和预发行版中按发布时间选最新一条，通知会标明“预发行版”。保存后点“检查并发布最新版本”，首次发送当前最新版本，后续只给尚未收到该版本的目标发送。固定置顶首条，长更新内容会分段保留。
4. 需要持续监测时打开“自动检查最新版本”并保存。默认每 **15 分钟**检查一次，支持 5～1440 分钟；不开启就没有定时检查。

平台原生表单执行按钮后可能只提示“已执行”，信息项不会即时刷新。“检查并发布最新版本”“查看发布记录”和“确认未发送并重试”的具体结果会写入“检查结果与发布记录”；**执行后请关闭并重新打开配置页查看具体结果**。“重新读取内置文档”的结果在“内置手册状态”查看。所有按钮使用已保存的配置，修改后请先保存。插件不修改平台页面，也不自建 Vue 界面。

## 自定义关键词回复

开启“启用关键词回复”后，在“关键词与回复内容”中逐条填写规则：

| 项目 | 填写方法 |
| --- | --- |
| 关键词 | 多个词用英文或中文逗号分隔，如 `最新版本,版本` |
| 匹配方式 | “完全一致”要求整条消息等于关键词；“包含关键词”在消息中出现关键词即可 |
| 回复内容 | 自定义文字，可换行；按纯文本发送，不解析 HTML 或 Markdown |

规则按列表顺序检查，命中第一条后停止，不重复回复，也不再进行 Wiki 检索。问题反馈前缀 `#bug反馈` 由反馈功能单独处理。

回复内容支持以下三个变量，其他文字按原样保留：

| 变量 | 内容 |
| --- | --- |
| `{version}` | 当前最新版本号，遵循“包含预发行版”设置及防旧缓存 |
| `{release_url}` | 对应的 GitHub 发布链接 |
| `{wiki_url}` | AWBotNest Wiki 地址 |

新配置自带两条可编辑的规则：“最新版本,版本”回复版本号与链接；“帮助”回复文档链接和问题反馈方式。开关未开启时不会自动回复。

关键词回复完整发送成功后，按“回复保留多少秒”登记清理，到期删除 **Bot 的答复和发送者的这条关键词触发消息**；其他聊天消息不受影响。**触发消息附带的图片或文件也会随整条消息一起删除，插件无法恢复。** 群内需给 Bot 删除消息权限。回复未完整发出或发送结果不明确时，不登记原消息清理。保留时间设为 `0` 后，后续答复与触发消息都不会进入自动清理队列。

## Wiki 问答

开启“启用 Wiki 问答”即可使用。根据插件内置手册匹配简明问答，回复**操作要点、手册版本和 Wiki 来源链接**，不粘贴长篇文档。每条答复保持简短（不超过 700 个 UTF-16 单位，普通中文字通常计 1 个、部分 Emoji 计 2 个）。不请求 GitHub Wiki、不额外调用 AI；没有可靠来源时提示补充问题，不编造答案。

当前内置 **v2.0.1.6 手册，共 11 篇文档、49 条简明问答**，问答覆盖这 11 个文档领域，每条附对应原文章节来源，随插件升级更新，没有定时在线同步。点击“重新读取内置文档”只重新加载插件包中的文件，不会下载在线 Wiki；在线 Wiki 更新后，需发布包含新手册与问答的插件版本，已安装的插件才能使用新内容。若内置文件缺失或损坏，会明确提示，不拿错误结果冒充答案。

支持功能别称和简短提问，也可以直接指定问答：

```text
/wiki 怎么安装平台
/问答 Cookie 怎么同步
@你的Bot用户名 插件装不上怎么办
```

将示例中的 Bot 用户名换成平台当前指定的 Bot。普通群聊按内置主题识别问题，不对每条聊天消息自动答复；明确指向其他 Bot 的命令不由本插件接管。Wiki 问题原文保留，只清理 Bot 的临时答复。

先匹配自定义关键词，未命中才检索 Wiki。发布通知与临时问答分开处理，用户提问不会触发群公告重发或重新置顶。

## 问题反馈给平台主人

开启“启用问题反馈”后，用户以 `#bug反馈` 开头提交问题，例如：

```text
#bug反馈
版本：v2.0.1.6
问题：插件保存后没有生效
操作步骤：修改设置，点击保存，再重新打开
报错：填写提示内容或附上相关说明
```

内容不规范时，Bot 会提示填写方式。反馈通知包含用户、来源群组、原消息链接（会话支持链接时）和问题正文；勿发送 Cookie、密码、API 密钥等敏感内容。

主人收件人读取平台“默认 Bot 私聊接收人”（`default_bot_chat_id`）；未填写时，由平台账号 SDK 解析首个账号的接收人。**只接受正数用户 ID，不把反馈发进默认公共群组。** 主人需先私聊该 Bot 并发送 `/start`，否则 Telegram 可能拒绝投递。只有实际投递成功才向用户确认“已送达”；失败会明确提示未送达，不能把接口调用完成当成成功。

主人收到的反馈通知不会自动删除；用户原始反馈也不会被插件删除。

## 回复范围与自动清理

“在哪些群组回复”每行填一个负数群组 ID 或 `@群组用户名`；留空沿用“发到哪些群组或频道”中实际属于群组的目标。Bot 私聊在启用任一回复功能后可用；频道广播不参与问答，频道的关联讨论群需单独填写。

要收到群内普通文字、关键词和 `#bug反馈`，请把 Bot 设为管理员，或在 BotFather 关闭 **Privacy Mode** 后重新加入群。Bot 必须在平台连接正常。插件不回复自身、其他机器人或匿名频道的消息，编辑旧消息不会重复触发。

临时回复默认 **60 秒后删除**；同一用户的默认回复间隔为 **15 秒**。清理范围如下：

- 自定义关键词：清理 Bot 答复及发送者的那条关键词触发消息，附带图片或文件随整条消息删除，插件无法恢复。
- Wiki 问答与问题反馈：仅清理 Bot 临时答复、填写提示和送达回执，用户问题与反馈原文保留。
- 发布公告（含置顶公告）、主人收到的反馈：不自动清理。

关键词触发消息在私聊可由 Bot 删除；普通群需 Bot 管理员，超级群需授予删除消息权限。Telegram 没有原子“双删”接口，删除某一条失败时会分别记录结果，不会冒充全部清理成功。无权限、消息不可删除等明确拒绝会停止重试；限流、网络中断等暂时错误按退避策略处理。

设置为 `0` 只让后续答复和关键词触发消息不再入队，不会撤销已有待删任务。手动把临时答复置顶，不会取消其自动清理；需要保留后续答复，请在发送前将保留时间设为 `0` 并保存。

待删消息保存在插件存储中，由一个平台托管后台任务处理，不为每条回复增加定时任务，也不每秒空跑。正常重启后恢复待删队列；插件停用期间不执行，重新启用后继续清理。Telegram 权限不足、网络中断等会影响实际删除，相关失败会记录日志；自动清理不等于消息已经无法被截图或转存。

## 最新版本与防重复

- 仓库固定为 `AWdress/AWBotNest`。关闭“包含预发行版”时使用 `releases/latest`；开启后读取发布列表的完整分页，按 `published_at` 选最新一条，不依赖列表顺序或旧提交的创建时间。草稿不会发送；达到 1000 条扫描上限仍无法确认列表完整性，或未能完整获取时停止发布，不冒充最新结果。
- 最新发布信息、GitHub ETag、逐目标发送进度和置顶状态保存在平台插件存储中，正常重载或重启后继续使用。接口返回旧版本时不会倒退发布缓存。
- 正式版和发布列表的条件缓存分开使用；切换开关不清除发送记录。关闭预发行后，如果当前正式版早于已处理的预发行版，会提示已阻止回退，不向任何目标重发旧正式版，也不会继续发送预发行缓存。等待更新正式版或重新打开开关即可。原有 0.0.1 缓存自动保留。
- 同一条 GitHub Release 从预发行改为正式版，只更新缓存，不重复通知；新建的发布仍须通过防旧检查。
- 同一个版本对每个目标只发送一次；新增目标可以收到当前最新版本。部分目标失败不会重发其他成功目标。
- 正文已发送但置顶失败时，后续只补置顶，不重复发送正文。长正文分段发送时保存进度，每轮合计最多发送 12 段；未完成的目标在下次自动检查或手动检查时续传。始终只处理当前最新版本；若有更新版本，不再继续旧版未完成的正文。
- 远端发送与本地存储无法组成一个事务。插件会先记录“发送中”；网络中断、超时或意外断电使发送结果不明确时，暂停该目标，避免自动重发。管理员必须先核对群组/频道：**只有确认未收到后，才使用“确认未发送并重试”**。盲目重试可能重复，不能保证绝对恰好一次投递。

插件停用时不执行任务；关闭自动检查则不创建版本检查任务，已启用的回复功能及待删消息清理不受此开关影响。卸载时若清除插件存储，发布记录与待删记录也会丢失；重新安装后首次检查可能再次发布当前最新版本。离线手册随插件包提供，不依赖之前的 Wiki 网络缓存。

## 监测开销

这不是持续抓网页或开浏览器的“实时监控”。默认 15 分钟检查一次，每天约 96 轮；正式版接口或 100 条以内的发布列表，每轮通常 1 次 GET，超过 100 条按页检查。使用 GitHub 条件请求，未更新时可返回 `304`，不发 Telegram 消息，不下载发布附件。通常在新版本发布后的一个检查间隔内发现。遇到 GitHub 限流或网络异常保留已有缓存，不把错误响应当成新版本。

Wiki 问答读取内置手册，不产生 GitHub Wiki 网络请求，不抓取网页或调用 AI；临时消息清理按最近到期时间等待。版本检查仍需访问 GitHub Releases，发送与删除仍需连接 Telegram，这些请求使用平台网络设置，Bot 凭据由平台读取。没有新增服务、浏览器进程或外部依赖。若版本检查或 Telegram 操作失败，请检查平台已有的网络/代理设置。

## 默认设置

| 设置 | 默认值 |
| --- | --- |
| 自动检查最新版本 | 关闭 |
| 包含预发行版 | 关闭；需要时开启并保存 |
| 目标群组或频道 | 空，需自行填写 |
| 检查间隔 | 15 分钟 |
| 发布后置顶 | 固有行为，置顶首条 |
| 运行状态 | 尚未检查 |
| 关键词回复 | 关闭；内置两条可编辑规则 |
| Wiki 问答 | 关闭；内置 v2.0.1.6 手册（11 篇、49 条问答） |
| 问题反馈 | 关闭；以 `#bug反馈` 开头 |
| 回复群组 | 空，沿用发布目标中的群组 |
| 回复保留时间 | 60 秒；关键词答复与触发消息到期双删，0 不登记后续清理 |
| 同一用户回复间隔 | 15 秒 |
| 内置手册状态 | 内置手册：v2.0.1.6（11篇） |
