# Telegram 助手

消息转发、删除消息、查 ID、消息结构、消息贴图、自动换头像和报时昵称。使用平台 Telegram 用户账号，不需要另配 Bot。功能开关默认关闭。

## 转发与置顶

在“消息转发”中启用规则转发，再添加规则。来源和目标填写 Telegram 数字 ID 或 `@用户名`，多个目标用逗号分隔。用户、Bot、群组和频道均可作为目标，当前账号需要能向目标发送消息。

每条规则可独立开启“自动置顶”。群组和频道要求当前账号是管理员或创建者，且具备 Telegram 允许的置顶权限；用户和 Bot 私聊只置顶当前账号这一侧，不替对方置顶。静默置顶，相册只置顶第一条；置顶失败只记录原因，不重发消息或中断其他目标。

## 全量历史转发

1. 在规则里开启“全量转发历史消息”，设置“全量发送间隔（秒）”，默认 3 秒，范围 1～3600 秒。开启“整组转发相册”后，每组相册算一次发送。
2. 保存配置后自动开始，按来源消息从旧到新转发。关键词、排除词、发送者、类型、复制搬运和自动置顶仍按本规则执行。
3. 初次开始时固定历史截止消息；后续新消息由实时转发处理。每个目标单独保存进度，重启后续传，已完成的目标不会重跑。
4. 关闭本条规则的全量开关并保存可暂停。普通发送失败时暂停该目标、继续其他目标；处理失败原因后点击“继续全量转发”。Telegram 限速时按服务端要求等待，实际间隔可能更长。

实时、遗漏补全和全量转发共享发送锁与逐消息投递账本。目标的 `@用户名` 与数字 ID 会统一识别；相册部分已投递时只发送剩余消息。账本存于插件的账号数据目录，超过内存最近 5000 条的记录仍能查询，不因长历史扫描而忘记已发消息。请保留插件数据目录，删除账本会丢失对应去重依据。

去重依据是插件已有的成功投递记录，不会凭相似文本猜测目标里手动转发过哪些内容。升级前没有保留的旧记录也无法凭空恢复。Telegram 发送与本地记录不能原子提交：若进程恰好在发送成功、账本写入前异常退出，仍需核对最后一条；正常重启和已落盘记录的续传不会主动重发。
